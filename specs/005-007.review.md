CONCERNS

Status: historical review. All ten concerns were addressed by the revised local
implementations recorded in specs 005, 006, and 007 on 2026-08-11.

1. **[Spec 005]** Importing `resolveOutputDir` from `scripts/build-pages.mjs` executes the module’s existing top-level build, including `rm`, `mkdir`, and copying. The proposed test therefore cannot satisfy “never call `rm` or create directories.” The spec must make the CLI body import-safe or move the resolver into a separate module.

2. **[Spec 005]** The guard blocks exact `"."`, `".."`, outside paths, and the current `PAGES_DIRS`, but it still permits destructive destinations. The repository’s `.audit` directory is missing from the reserved list; root files such as `app.js` and `package.json` are accepted and would be deleted before becoming directories; and case-sensitive comparison lets `"Scripts"` target the real `scripts` directory on Windows. This does not implement the audit requirement to permit only an explicit safe staging destination.

3. **[Spec 005]** The four destructive CLI checks are unsafe against an implementation whose guard is wrong: the first command could delete `C:\Users\Jace\dev`. Each compound `node ... ; echo ...` command also exits successfully because `echo` is last, regardless of the Node exit status. The normal-build command has the same fail-loud defect. These checks need an isolated disposable fixture and explicit shell assertions. The `npm test` baseline is correctly 148 tests and can pass; `git status --porcelain` only prints state and does not assert it.

4. **[Spec 006]** The local-array arithmetic is wrong. `.claude/settings.local.json` currently has 63 allow entries, so removing seven leaves **56**, not 34. The verification command also checks only five of the seven removals, omitting the exact `gh pr create ...` and `sed -i ... probe.mjs` entries. Its stated expectation cannot pass after a correct implementation.

5. **[Spec 006]** The tracked-settings check verifies only `denyCount=12`, not that the four required deny rules exist or that the eight existing rules remain. Twelve arbitrary rules would pass. The JSON parse checks are valid, but `npm test` tests no permission behavior, and `git status` cannot prove the ignored local file was edited correctly.

6. **[Spec 006]** Deny precedence is correctly described: a machine-local allow cannot override these denies. However, denies block commands rather than requiring human approval. Claude Code supports tracked `ask` rules, which are evaluated before allows and can force approval despite a local allow. That matches the stated goal better. As written, merge, close, `taskkill`, and every `build-pages` invocation become unapprovable; the last also conflicts with spec 005’s verification. Conversely, push and checkout are protected only by deleting today’s local allows and can be auto-allowed locally again. Phase 6 push remains initially promptable, while Phase 5 itself contains no branch-creation command—the spec’s Phase 5 rationale is factually wrong. [Claude Code permission rules](https://code.claude.com/docs/en/permissions)

7. **[Spec 006]** The goal that arbitrary code requires approval is not achieved. After the seven removals, executable allowances remain for `codex exec *`, `node probe.mjs`, `python -`, and `node /tmp/doctor-jsj/proj.cjs`; the latter two Node script paths are mutable. Either narrow the goal to the broad `node -e` rule or address the remaining execution paths explicitly.

8. **[Spec 007]** `HANDOFF.md`’s third `v78` is a historical entry describing what release v78 contained. Replacing it with `v79` falsifies version history. A v79 history entry should be added while the v78 entry remains unchanged. Consequently, the proposed “no `v78` anywhere” grep is conceptually wrong.

9. **[Spec 007]** The fourteen files contain all current `v78`/`?v=78` matches, but several claimed occurrence counts are matching-line counts, not occurrences: `sw.js` has **38**, not 37; `test/service-worker.test.mjs` has **14**, not 13; and `AGENTS.md` has **6**, not 5. `test/release-integrity.test.mjs` has 19 occurrences under the stated pattern, plus three standalone `"78"` literals, for 22 required numeric replacements. `AGENTS.md` also has one standalone backticked `78`, making seven edits there. Adding only `test/service-worker.test.mjs` does not make AGENTS’ future bump list complete—it still omits `AGENTS.md` itself and both documentation files that this spec requires updating.

10. **[Spec 007]** Verification is not fail-loud or fully probative. `npm test` checks runtime references but not the three documentation files. The no-v78 grep misses AGENTS’ standalone `` `78` `` and its trailing `echo` makes the compound command exit zero whether matches remain or not. `git grep -c ... -- sw.js` prints `sw.js:1`, not `1`, and exits zero for any positive count, including an incorrect count of two. The marker Node command is valid and fail-loud; `git status --porcelain` is only a manual listing, not an exact fourteen-file assertion.
